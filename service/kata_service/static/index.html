01 · Rationale

Decision rationale and trust score

A verify check can return a rationale with the decision. The rationale lists the reason codes already on that decision, a score from 0 to 1, and references to evidence stored for that decision. That score is computed with deterministic rules from the reason codes, the agent's trust score, and the stored evidence result. That score is not a calibrated probability. The same inputs always return the same score. When no evidence is stored, the evidence list is empty and the verdict is unchanged. The trust score is an integer from 0 to 1000 on the agent, also computed with deterministic rules. Individuals are not scored.

Rule sandbox

The rule sandbox tests a candidate rule on synthetic data before that rule is enabled. Supply a seed and a count, or a synthetic batch of at most 100 requests. The replay does not read per-agent intents, participant records, or the ledger, and it does not write evidence or change the rules in use.

03 · Authority

Agent authority ladder

The agent authority ladder assigns a level from 0 to 3, and a level only tightens the verify decision. It does not turn a deny into an allow, and it does not turn a step-up into an allow. Level 0 denies a payment that is not already denied, with AUTHORITY_OBSERVE_ONLY. Level 1 steps up a payment that would have been allowed, with AUTHORITY_STEP_UP. Level 2 allows only under a per-transaction ceiling of 100 and a cumulative ceiling of 100, and only at or under an approval threshold of 25. Those ceilings do not exceed that agent's signed intent maximum or agreement cumulative limit. Above the threshold the result is step-up, with AUTHORITY_APPROVAL_REQUIRED. Above a ceiling, when the decision would have been allow, the result is deny, with AUTHORITY_TX_LIMIT or AUTHORITY_CUMULATIVE_LIMIT. Level 3 leaves the decision unchanged. An agent with no level also leaves the decision unchanged. A per-agent stop denies later checks for that agent only, with AGENT_STOPPED. Resume lifts that stop. If the level itself cannot be read, the result is step-up with AGENT_AUTHORITY_UNAVAILABLE, and it is not an allow.

04 · Approval

Human-approval hold and release queue

A verify that is already step-up can be placed in a hold, and the response adds a hold_id. Allow and deny responses stay unchanged. Approve and reject are an admin review. Each one requires a reviewer id and a reason. The approval is bound to that decision's decision_ref and payload_hash. A different amount, a different payee, or any other payload change cannot use it. Release is single-use. A second release is answered with 409. Before a release returns allow, the check reads agent stop and authority, intent and agreement limits, and cumulative spend again. If any of those fail, the release is deny with that reason code. The default hold lifetime is 900 seconds. An expired hold returns deny with HOLD_EXPIRED, and it is not an allow. If the hold store cannot be reached, the result is step-up with HOLD_UNAVAILABLE, and it is not an allow.

Phase 1

Phase 1 Web Bot Auth verification

Web Bot Auth verification checks an Ed25519 HTTP message signature, RFC 9421. Signature-Agent names the directory that publishes the public key. An origin publishes that directory at /.well-known/http-message-signatures-directory. The published key is a public Ed25519 JWK. A private key is refused and is not published. The created and expires parameters must sit within 60 seconds of the clock. A signature that verifies identifies the signer. The payment still has to match the signed intent.
