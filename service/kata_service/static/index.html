Dispute evidence

Kept with the agent

A dispute keeps the signed record with the agent. Evidence is the intent, the payment, and the outcome, linked to the agent. A report that is not linked to an agent is rejected. Participants can inquire for dispute resolution with a purpose code. An inquiry does not change the score.

Linked

Chargeback on shopper-01

The signed ceiling, the payment, and the outcome stay on the same agent. Chargeback for the laptop payment at techstore.example.

Rejected

Report with no agent

An unlinked report is not evidence. It does not enter the record.

Inquiry

Purpose code required

Dispute resolution is one purpose. The inquiry does not change the score.

The service

Explore the site for what is published now.

Documentation, status, and the simulation are on this site. KATA is the framework underneath the checks, licensed under PolyForm Noncommercial.

MCP

5 tools, remote

POST /mcp is a remote MCP server over streamable HTTP. The 5 tools are verify agent, inquire, report, check revocation, and fetch a signed receipt. The tools require a bearer API key.

Sandbox

gab_test_ keys

Test keys use the gab_test_ prefix. Live keys use the gab_ prefix. Live and test rows stay isolated. A test report does not change a live score. When GAB_ENV is sandbox, only a gab_test_ key is accepted.

Health

/health and /status

GET /health and GET /v1/health need no API key. The same reading is on /status.

Limits

Retry-After on 429

Defaults are 60 verifies, 30 inquiries, and 10 reports each minute, and 120 requests overall. A limit answers 429 with Retry-After: 60.

UCP

Sandbox checkout check

In the sandbox, the bureau verifies a Universal Commerce Protocol checkout as an action. It does not host checkout. The path accepts a gab_test_ key only.
